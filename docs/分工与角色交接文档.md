## 1. 事实快照(项目现状,AI 的公共上下文)

### 1.1 一句话定位
装在华为手机/平板(后续 PC)的 AI 助理,命题为"基于鸿蒙原生智能的多模态个人助理"。核心卖点:**端侧优先、数据不出设备、回答带出处**。全 ArkTS 工程,仓库根 `Harmony_Agent`。

### 1.2 命题四大能力 vs 现状
| 命题能力 | 现状 |
|---|---|
| 多模态交互(语音/文本/图像+复合指令) | 文本✅;语音=代码完成**待真机**;图像=OCR 浅层✅(识图按钮);复合指令见 1.5 缺口 |
| 端侧 RAG 知识库 | 自研版本✅(导入/切块/关键词检索/引用溯源/文档预览);官方 DataAugmentationKit **未接入**(方案已定,加工端缺 PC/2in1) |
| 跨设备协同 | ❌ 未实现(仅一多布局完成:平板双栏/手机单栏) |
| ≥3 子智能体协作 | 浅层✅(路由+单 Agent 串行步骤);**跨子 Agent 协作/自主分解未实现** ← 最大缺口 |

### 1.3 技术栈与关键决策
- 语言/UI:全 ArkTS(严格模式);Provider 双实现策略 = 真机实现 / 模拟器降级,靠 `CapabilityManager` 探测切换
- LLM:`LLMProvider` 接口,现实现 Mock / DeepSeek(默认开启开关在 `LlmConfig.ets` `ENABLE_DEEPSEEK`,当前为 false)/ Pangu(占位);D8 已做 **streamChat 流式**(DeepSeek 真 SSE + Mock 打字机)
- 知识库定位(重要口径):**"知识来源"与"加工引擎"解耦**。个人资料(课程笔记/文献/纪要)靠自采自建,官方 DataAugmentationKit 只是可选加工引擎,用于满足"语义检索 + 使用鸿蒙 RAG 模块"两条硬要求
- D5 官方分端架构:加工(knowledgeProcessor)**仅 HarmonyOS PC/2in1 可跑** → 产物拷到手机 → 手机用 retrieval 检索;无 PC/2in1 时演示走自研检索(已可跑)
